Part 1: Ray Generation and Scene Intersection

The main idea of our ray generation method is that for any given normalized coordinates, we first translate to camera space, then generate the ray in camera space, and finally transform the ray into world space. To do this, first we define an axis aligned virtual camera sensor and use hFov and vFov, the field of the view angles along the X and Y axis. we can set the bottom left and top right corners using the following: \[ ws = tan(hFov/2), hs = tan(vFov/2) \] Afterwards we will define the following ray then use the camera sensor's camera-to-world rotation matrix to transform it: \[ ((2x - 1)ws, (2y-1)hs, -1)\] For the triangle intersection algorithm, consider a ray written out as the following: \[r(t) = o + td\] Where o is the origin of the ray and d is the direction of the ray. The idea is to solve for u, v, and t variable such that: \[0 \leq u \leq 1\] \[v > 0\] \[u + v \leq 1\] \[\text{min_t} < t < \text{min_t}\]

To find \(u\), \(v\), and \(t\), we write the intersection point on the triangle using barycentric coordinates:

\[ p = (1-u-v)p_1 + up_2 + vp_3 \]

Since the same point must also lie on the ray, we set:

\[ o + td = (1-u-v)p_1 + up_2 + vp_3 \]

Rearranging gives:

\[ o - p_1 = u(p_2 - p_1) + v(p_3 - p_1) - td \]

This can be written as a linear system:

\[ \begin{bmatrix} p_2 - p_1 & p_3 - p_1 & -d \end{bmatrix} \begin{bmatrix} u \\ v \\ t \end{bmatrix} = o - p_1 \]

Solving this system will give us the values for \(u\), \(v\), and \(t\).

Part 2: Bounding Volume Hierarchy

To build a Bounding Volume Hierarchy (BVH) instance, I use a recursive function that takes a range of primitives and the maximum leaf size configuration. The algorithm will first build a bounding box, encloses all primitives in the given range, then create a BVH node in the bounding box. For the Base Case, if the given range of primitives are less than the maximum leaf size (or making a leaf node), the node's children are set to null and is returned. The splitting heuristic will take a centroid bounding box, and take a 3D vector of its range, then split on the highest value axis on that range. This represents the axis with the most varied points. The primitives are paritioned around the midpoint along the axis into the left and right subsets, and a recursive call is made on both of the node's children and the max range set to the midpoint.

Part 3: Direct Illumination

Next, I implemented 2 different versions of a direct illumination function for introducing light sources into scenes. The first method is a direct lighting function that uses uniform hemisphere sampling. The central idea is to sample incoming light directions uniformly in a hemisphere above the object surface and using Monte Carlo Estimation to calculate each sample's BSDF contribution and average across all samples to find our outgoing illumination vector.

Lout = (2π / N) Σi=1N f(wout, wi) Li cos(θi)

For every sample in the scene, I will uniformly sample the 3D vector representing a light direction, transfer to world coordinates, create its corresponding shadow ray, and check if the shadow is occluded. If so, we'll calculate it's BSDF contribution and average all the samples at the end.

The next method was direct lighting by sampling the "importance" of lights, or sampling only the light directions that hit a point p. The previous method will lead to a noisy output, so the purpose of sampling by importance is to eliminate noisy features by only considering the light directions that will actually reach a hit point. First we find the 3D vector that's between the light source and hit point, transfer that to the world coordinates. Then we create the corresponding shadow but instead only calculate the BSDF contribution if the shadow is not occluded.

The significant difference between the hemisphere and light sampling is the amount of noise. Due to the hemisphere sampling selecting uniformly at random, it will incorporate a lot of random noise vectors, which leads to a "fuzzier" image quality (the black spots all over the scene). Light sampling will only consider light directions that make contact with a surface, therefore eliminating the random patches of black in the image and producing a clearer scene. Where hemisphere sampling excels is that it will work for all lighting types and will produce a unbiased estimate of radiance, however for scene creation the light sampling is the better choice.

Part 4: Global Illumination

To extend the previous part regarding direct illumination methods, this part centers on Global illumination which we now also account for indirect illumination. First I made a new sampling method that not only returns the proportion of incoming light scattered from an indicent direction to an outgoing direction, but also updates the Probability Density Function (PDF) of the sample. This lets us calculate the unbiased Monte Carlo Estimation for indirect lighting:
Lo(p, ωo) = Le(p, ωo) + ∫Ω fr(ωo, ωi) Li(p, ωi) cos(θi) dωi
Lo ≈ Le + ( fr(ωo, ωi) Li(ωi) cos(θi) ) / pdf(ωi)
Then I develop a recursive function that will now also account for whether we want light to accumulate to a max depth. For a base case, we use the previous one bounce radiance method from the last part if the ray depth is 0 or 1. Otherwise we use our new sampling function to get a new direction, transfer that to world space, spawn a new ray from the hit point in this direction, recursively evaluate the incoming radiance from that ray, and finally Weight the contribution using the BSDF, cosine term, and PDF. If we want light to accumulate, we will sum up each vector returned from the recursive calls, otherwise we return the final vector returned.

Here is CBunny.dae using Russian Roulette global illumination with different max depths. The Russian Roulette algorithm differs from our traditional global illumination method, as it now incoporates random termination of rays depending on a constant probability. At each bounce beyond a certain depth, a ray will be terminated with probability p. If a ray is not terminated, it's intensity is increased to compensate for the loss of rays. This reduces the computation time from the previous method, while still maintaining its ability to light a scene without bias. For these images, I use a termination probability of 0.4 or 40% of samples.
