For the first part of this assignment, I designed a function that will take a cloth's parameters and build an evenly spaced grid of masses and springs. This function is split into 2 parts: building mass and building springs. To build the mass portion, I iterate through every grid location and convert their coordinates into normalized coordinates u and v. For horizontal cloths, I place the point mass at (X, 1, Y). Otherwise I place it at (X, Y, z) where z is a small offset.

Then for the spring portion, I iterate through each point mass again and connnect them to the following neighbors based on the constaints below:

Left and Above Neighbors => Structual Spring

Upper Left and Upper Right Neighbors => Shearing Spring

Two-Left and Two-Above Neighbors => Bending Spring

Part 2: Simulation via numerical integration

After modeling our cloth as a grid of masses and springs, the cloth needs to now handle forces being applied to it's point masses to show bending. To do this we need to integrate the physical equations of motion and apply those to each point mass. First, we compute the total external forces and apply it to each point mass. Then we iterate through each spring and apply a spring correction force to the point masses. \[ F_{ext} = ma \] \[ F_{s} = k_{s} * (||p_{b} - p_{a}|| - l)\]

$k_s$ is the spring constant, $p_b$ and $p_a$ are the 2 masses on the springs' ends, and l is the spring's rest length

Next, we apply Verlet Integration to compute new point mass positions. For each unpinned point mass, we will update its position using the following

\[x_{t+dt} = x_{t} + (1 - d) * (x_{t} - x_{t-dt}) + a_{t}*dt^2 \]

d is a damping term between 0 and 1. Finally, we will constrain the spring changes such that the spring length does not increase by more than 10%.

Below is a series of different images showcasing how a cloth falls with 2 pinned corners using different parameters. This set shows differences between a low and high spring constant values. One key difference between these a low density and a high density is how the middle portion collapses. The lower density leads to weaker springs and therefore dips farther, whereas a higher density leads to a more upright cloth.

This set shows differences betweena low and high density values. Varying density had a similar effect to varying the spring constaints as a lower density allowed for lighter point masses in the springs which leads to gravitational forces having less impact. A higher density therefore means heavier point masses and therefore more prominent effects from gravity, making the cloth sag more.

This set shows differences betweena low and high damping values. The significant change for varying damping was actually the time it took to collapse. A high damping rate had slowed the falling process significantly, unlike a low damping rate that allowed the cloth to quickly fall to rest.

Part 3: Handling collisions with other objects

This part centers on handling collosions with standard shapes in the simulation space. The first object that I added cloth collision for was spheres. Handling sphere collosion required a collide function in the sphere datastructure to be filled in. This function has to take a point and adjusts its position if it collides with or is inside a sphere. First, it will compute the vector between the point mass and the sphere's origin, and "bump" it to the sphere's surface if it intersects. Otherwise, it will skip the point Afterwards, it will get the vector's tangent point to the sphere in order to compute a correction vector. The function will adjust the point mass' position by the correction vector scaled down to (1 - friction). \[ Correction Vector = Tangent Point - Last Position \] \[ Position = Last Position + Correction Vector * (1 - f)\]

The following images are different sphere collosion tests with the default ks value (5000), a low ks value (500), and a high ks value (50000). As we saw in the last part, higher ks values leads to stronger springs comprising the cloth grid, which will lead to the cloth able to hold its shape better as the simulator handles the sphere collosion.

The next collosion method implemented was one to handle plane collisions. Instead, this collision function will detect to see if the point mass crossed the Plane. If a point crosses a plane, we will "bump" it up to the surface. We'll compute the tangent point and compute a correction vector. However, to reach a point slightly above the tangent point before crossing the plane, we will also apply a small surface offset value to the correction vector. Then we will update the point mass' position with the correction vector scaled by (1 - friction). Below shows our cloth as a wireframe laying flat on a plane.

Part 4: Handling self-collisions

The final collision feature implemented was the self collision procedure. To do this, I use an spatial hashing method, which will build a hashtable that maps a float to a vector of point masses The float represents a 3D volume in the scene and the vector stores point masses in that 3D space.

First, the Cloth data structure now features a hash_position function, which will be what maps a point mass' position to the 3D volume float. It was paritition the space into 3D boxes of the following size:

\[ Volume = w * h * t \] \[ w = \frac{3 \cdot \text{width}}{N_{\text{width}}} \] \[ h = \frac{3 \cdot \text{height}}{N_{\text{height}}} \] \[ t = max(w, h) \]

The point mass is truncated to the closest 3D box, and each element of the coordinate is scaled by large distinct prime numbers to ensure unique key creation. Next, we build a function that will build the spatial map by calling hash_position() on every point mass. Finally, the cloth structure also uses a self_collide() method that will use the hash table to separate points that are too close. It will assess a point mass and its potential candidate points and determine if any candidate points are within double the cloth thickness from the point mass. If so, it will apply a correction vector to the point mass' position to separate them. If there are multiple, the function will average all the correction vectors and scale the result by total number of simulation steps.
