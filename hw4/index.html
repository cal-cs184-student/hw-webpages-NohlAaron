Overview

For the final homework assignment, I develop a real-time cloth simulator that uses masses and springs to build a grid representing cloth. Beyond defining the cloth data structure, I also simulate real-world physics on the cloth using numerical integrate, allowing for the simulator to display cloth bending, folding, and falling. Finally, I modify other 3D objects in the simulator to handle collisions with cloth, along with enabling the cloth to handle self collisions. This allows for cloths to cover objects and properly fold onto themselves. The most interesting part of this project was the shaders section, as I learned a lot about how colors can replicate into lighting/shading effects, as well as create unique textures along surfaces.

Part 1: Masses and springs

For the first part of this assignment, I designed a function that will take a cloth's parameters and build an evenly spaced grid of masses and springs. This function is split into 2 parts: building mass and building springs. To build the mass portion, I iterate through every grid location and convert their coordinates into normalized coordinates u and v. For horizontal cloths, I place the point mass at (X, 1, Y). Otherwise I place it at (X, Y, z) where z is a small offset.

Then for the spring portion, I iterate through each point mass again and connnect them to the following neighbors based on the constaints below:

Left and Above Neighbors => Structual Spring

Upper Left and Upper Right Neighbors => Shearing Spring

Two-Left and Two-Above Neighbors => Bending Spring

Here are some screenshots of a basic mass and spring grid. Notice the shearing constraint removes the diagonal lines within the squares, and all 3 constraints will destroy the grid.

Part 2: Simulation via numerical integration

After modeling our cloth as a grid of masses and springs, the cloth needs to now handle forces being applied to it's point masses to show bending. To do this we need to integrate the physical equations of motion and apply those to each point mass. First, we compute the total external forces and apply it to each point mass. Then we iterate through each spring and apply a spring correction force to the point masses. \[ F_{ext} = ma \] \[ F_{s} = k_{s} * (||p_{b} - p_{a}|| - l)\]

\(k_{s}\) is the spring constant, \(p_{b}\) and \(p_{a}\) are the 2 masses on the springs' ends, and l is the spring's rest length

Next, we apply Verlet Integration to compute new point mass positions. For each unpinned point mass, we will update its position using the following

\[x_{t+dt} = x_{t} + (1 - d) * (x_{t} - x_{t-dt}) + a_{t}*dt^2 \]

d is a damping term between 0 and 1. Finally, we will constrain the spring changes such that the spring length does not increase by more than 10%.

One key difference between these a low density and a high density is how the middle portion collapses. The lower density leads to weaker springs and therefore dips farther, whereas a higher density leads to a more upright cloth.

Part 3: Handling collisions with other objects

This part centers on handling collosions with standard shapes in the simulation space. The first object that I added cloth collision for was spheres. Handling sphere collosion required a collide function in the sphere datastructure to be filled in. This function has to take a point and adjusts its position if it collides with or is inside a sphere. First, it will compute the vector between the point mass and the sphere's origin, and "bump" it to the sphere's surface if it intersects. Otherwise, it will skip the point Afterwards, it will get the vector's tangent point to the sphere in order to compute a correction vector. The function will adjust the point mass' position by the correction vector scaled down to (1 - friction). \[ Correction Vector = Tangent Point - Last Position \] \[ Position = Last Position + Correction Vector * (1 - f)\]

The following images are different sphere collosion tests with the default ks value (5000), a low ks value (500), and a high ks value (50000). As we saw in the last part, higher ks values leads to stronger springs comprising the cloth grid, which will lead to the cloth able to hold its shape better as the simulator handles the sphere collosion.

The next collosion method implemented was one to handle plane collisions. Instead, this collision function will detect to see if the point mass crossed the Plane. If a point crosses a plane, we will "bump" it up to the surface. We'll compute the tangent point and compute a correction vector. However, to reach a point slightly above the tangent point before crossing the plane, we will also apply a small surface offset value to the correction vector. Then we will update the point mass' position with the correction vector scaled by (1 - friction). Below shows our cloth as a wireframe laying flat on a plane.

Part 4: Handling self-collisions

The final collision feature implemented was the self collision procedure. To do this, I use an spatial hashing method, which will build a hashtable that maps a float to a vector of point masses The float represents a 3D volume in the scene and the vector stores point masses in that 3D space.

First, the Cloth data structure now features a hash_position function, which will be what maps a point mass' position to the 3D volume float. It was paritition the space into 3D boxes of the following size:

\[ Volume = w * h * t \] \[ w = \frac{3 \cdot \text{width}}{N_{\text{width}}} \] \[ h = \frac{3 \cdot \text{height}}{N_{\text{height}}} \] \[ t = max(w, h) \]

The point mass is truncated to the closest 3D box, and each element of the coordinate is scaled by large distinct prime numbers to ensure unique key creation. Next, we build a function that will build the spatial map by calling hash_position() on every point mass. Finally, the cloth structure also uses a self_collide() method that will use the hash table to separate points that are too close. It will assess a point mass and its potential candidate points and determine if any candidate points are within double the cloth thickness from the point mass. If so, it will apply a correction vector to the point mass' position to separate them. If there are multiple, the function will average all the correction vectors and scale the result by total number of simulation steps.

Part 5: Shaders

In this part, I experiment with different shader programs built within the GPU. A shader is a program that will run in parallel on the GPU during the graphics pipeline. The shader program will take an input and output a 4 dimensional vector, which represents a color that will resemble shading on objects or special textures. This part will go over 2 different shader types: vertex and fragment. A vertex shader will modify geometric properties like positions and normal vectors, and will store varyings for use in the fragment shader. Fragment shaders will take geometric attributes of the fragment calculated by the vertex shader, and compute a color to apply to pixels.

The first shading option I implemented was a Blinn-Phong shading model. The overall idea of Blinn-Phong is to utilize this equation to calculate the final vector:

\[ L = \text{Ambient} + \text{Diffuse} + \text{Specular} \] \[ L = k_a I_a + k_d \frac{I}{r^2} \max(0, \mathbf{n} \cdot \mathbf{l}) + k_s \frac{I}{r^2} \max(0, \mathbf{n} \cdot \mathbf{h})^p \]

\( \frac{I}{r^2} \) represents the attenuated light intensity, where \( I \) is the light’s intensity and \( r \) is the distance from the light source. The dot products represent the angles between the surface normal and the light direction (\( \mathbf{n} \cdot \mathbf{l} \)) and between the surface normal and the half-vector (\( \mathbf{n} \cdot \mathbf{h} \)). The half-vector \( \mathbf{h} \) is defined as the normalized average of the light direction and the view direction. \(k_{a}\), \(k_{d}\), \(k_{s}\), \(I_{a}\), and p are all constants that control the strength of each component. These are tuned by me within the script. Below I show the cloth and sphere simulation using the different elements of the Blinn-Phong model.

The next method I implemented was texture mapping, which will take a custom texture as a png and apply it to objects in the space. For this example, I use a photo of my dog to showcase the mapping working on our cloth and sphere simulation.

Knuckles helps a lot for the next methods as well, but mainly because the photo features a wooded floor and fuzzy bean bag. Bump mapping and Displacement mapping will modify the Blinn-Phong model from earlier. Bump Mapping will perturb the surface normals by building a tangent-bitangent-normal matrix (TBN), then computing the following in (u,v):

\[ dU = \left(h\left(u + \frac{1}{w}, v\right) - h(u, v)\right) \cdot k_h \cdot k_n \] \[ dV = \left(h\left(u, v + \frac{1}{h}\right) - h(u, v)\right) \cdot k_h \cdot k_n \] \[ \mathbf{n_o} = (-dU, -dV, 1) \] \[ \mathbf{n_d} = \text{TBN} \cdot \mathbf{n_o} \]

h(u,v) is a function that will return the height encoded in the height map by (u,v). \(k_{h}\) is a height scaling factor, \(k_{n}\) is a normal scaling factor. \(n_{d}\) is the space normal that will be passed into the Blinn-Phong Model.

Displacement mapping will use the bump.frag model, and instead use a modified vertex shader that will displace the vertex positions in their original directions by the scaling variable:

\[ \mathbf{p'} = \mathbf{p} + \mathbf{n} \cdot h(u, v) \cdot k_h \]

Below showcases Knuckles being used in combination with Bump Mapping and Displacement Mapping.

As seen from above, The wood texture appears along the edges while the bean bag fuz sits along the top of the cloth. This gives the cloth a look that ressembles a bathroom towel. Bump mapping will maintain the overall shape of the cloth, whereas displacement mapping will distort the cloth geometry along the pieces of the texturing. We see these effects much clear when adjust the sphere coarseness, as a higher sphere coarseness results in more defined texutring in bump mapping, and more geometry distortion in the displacement mapping.

Finally, I implement a mirror shader, which will compute a reflection vector from the surface normal and view direction. It will sample an environment map in the direction of the reflection vector, which results in displaying a reflective surface.
